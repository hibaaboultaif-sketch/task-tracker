# Reflection

For this project, I used Cursor's built-in AI agent (Composer) as my primary coding assistant, working through Claude in a separate chat as a guide for planning each step, reviewing AI output, and troubleshooting errors before applying changes. The AI agent handled the actual code generation inside Cursor , writing the Pydantic models, FastAPI endpoints, and pytest tests — while I reviewed each diff before accepting it and ran the app or tests myself to confirm the behavior matched what was asked.

One moment where AI genuinely helped was in scaffolding the pytest suite for the new tags and due-date features. Writing eight new test functions by hand would have taken much longer, and the AI correctly followed the existing test file's patterns (using the shared `client` fixture, the `reset_task_storage` autouse fixture, and consistent naming conventions), which meant the new tests integrated cleanly with almost no manual rework.

One moment where AI slowed me down was during the CORS troubleshooting. My first fix attempt from the AI's edit landed the `CORSMiddleware` import and `app.add_middleware()` call in the wrong place structurally, causing an `IndentationError` when the server tried to start. It took two more rounds of edits (and one accidental paste of documentation markdown into `main.py` instead of its intended file) before the server ran cleanly again. In hindsight, a smaller, single-purpose edit request rather than one combined prompt would likely have avoided the structural mixup.

One place where my review actually changed the result was in the `compute_is_overdue` logic. The AI's first draft computed overdue status purely by comparing the due date to today's date, with no consideration of the task's current status. I caught that this would incorrectly flag a completed task as overdue if its due date had passed before it was finished — which doesn't make sense from a user's perspective, since a "Done" task shouldn't need attention regardless of when it was originally due. I asked for an explicit status check to be added, and the corrected version now returns `False` for any task in the "Done" state before it even evaluates the date comparison. This is exactly the kind of assumption-correction the course asks students to catch rather than accept blindly.

Overall, the process reinforced that AI-generated code needs active verification at every layer , reading the diff, running the actual server, and testing edge cases myself — rather than trusting a natural-language summary of what the code does.
